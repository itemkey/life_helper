# life_helper

## Сохранность данных при обновлении

PostgreSQL хранит списки в именованном томе `postgres_data` из `docker-compose.yml`.
Пересборка контейнера бота не должна удалять этот том. Не запускайте `docker compose down -v`
и не удаляйте том вручную: вместе с ним исчезнет база данных.

Перед обновлением работающего бота сохраните резервную копию PostgreSQL вне сервера и
убедитесь, что её можно восстановить. Контейнер бота при запуске выполняет
`alembic upgrade head`; поэтому сначала проверьте, какие миграции будут применены.
Миграция `0009_list_price_mode` добавляет к спискам только поле `prices_enabled`.
Для существующих списков оно автоматически получает значение `true`: прежний режим
учёта денег, пункты, взносы и траты сохраняются. Переключение списка в режим без цен
не удаляет денежные записи; они снова доступны после включения учёта денег.

Миграция `0010_list_audit` создаёт отдельную таблицу журнала аудита. Она читает
сохранившиеся списки, разделы, пункты, взносы, траты и записи об участниках и
добавляет их в журнал как архивные события. Исходные таблицы и записи миграция
не меняет. Старые переименования, промежуточные отметки и уже удалённые записи
восстановить невозможно: до этой миграции они не сохранялись. Дальнейшие действия
со списком, разделами, пунктами, деньгами и участниками фиксируются в журнале.
Автоматический откат миграции запрещён, чтобы
не удалить накопленную историю аудита.

Миграция `0011_collapsed_list_sections` добавляет только новую таблицу для личного
состояния свёрнутых разделов. Существующие списки, разделы, пункты и денежные
записи она не изменяет. Сворачивание раздела одним участником не влияет на вид
списка у других участников.

Миграция `0012_list_view_page` добавляет номер страницы к сохранённому виду списка.
Для существующих сообщений он равен нулю; сами списки и пункты миграция не меняет.
